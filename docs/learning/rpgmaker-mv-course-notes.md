# 알만툴(RPG Maker MV) 강좌 학습 노트

- 대상: YouTube 재생목록 "알만툴mv강좌"(작긔, SE.01) 22편 중 1~13화
- 방법: 한국어 자동 자막을 읽고 제 말로 요약했다. 원문 자막은 저장하지 않았다.
- 미수집: 14~22화. 13화 이후 YouTube가 이 PC의 자막 요청을 막았다(IP 차단 응답). 시간이 지난 뒤 다시 받는다.
- 편집기 본체는 유료이고 약관상 리버스 엔지니어링이 금지되어 분석하지 않는다. 여기서 얻는 것은 "게임을 만드는 사고방식"이고, 구현은 오픈소스 엔진(RPG-JS 후보)과 우리 코드로 한다.

## 1. 핵심 모델: 맵 + 이벤트 + 스위치/변수

알만툴 게임은 거의 전부 세 가지 조합으로 만든다.

| 요소 | 뜻 | 우리 게임에서 대응 |
|---|---|---|
| 맵(타일) | 지형, 통과 가능 여부, 높이(캐릭터 아래·같은 높이·위) | Tiled 맵, 충돌 레이어 |
| 이벤트 | 맵 위 한 칸에 놓인 객체. 그림 + 실행 조건 + 명령 목록 | NPC·상자·발판·문·적 |
| 스위치·변수 | 전역 상태(맵을 넘어 유지). 셀프 스위치 A~D는 이벤트 하나만의 상태 | 게임 상태 저장소(순수 함수로 갱신) |

이벤트 한 개는 여러 "페이지"를 가지며, 조건을 만족하는 페이지 중 번호가 가장 큰 것이 적용된다. 즉 **이벤트 = 조건부 상태기계**다. 문이 닫힘 → 열림, 상자가 닫힘 → 빈 상자로 바뀌는 것이 모두 페이지 전환이다.

## 2. 트리거 5종

- 결정 버튼: 앞에 서서 버튼을 누를 때(대화, 조사)
- 플레이어 접촉: 밟거나 부딪힐 때(발판, 함정)
- 이벤트 접촉: 이벤트가 플레이어에게 닿을 때(추적하는 적)
- 자동 실행: 조건이 맞으면 즉시, 다른 조작을 막고 실행(컷신)
- 병렬 처리: 다른 일과 함께 계속 돈다(타이머 감시, 걸으면서 대화)

자동 실행·병렬 처리는 조건을 끄지 않으면 무한 반복되므로, 끝에 스위치를 꺼서 페이지를 바꾸는 것이 기본 패턴이다.

## 3. 화별 요점

| 화 | 주제 | 배운 패턴 |
|---|---|---|
| 1 | 맵칩 | 펜·사각형·채우기로 지형. 맵 속성(BGM·전투 배경·루프) |
| 2 | 이벤트·대화창 | 이미지·이동 옵션·우선순위·트리거, 대화 명령 |
| 3 | 장소 이동·캐릭터 이동 | 장소 이동(방향·페이드), 이동 루트(반복·막히면 건너뛰기·점프) |
| 4 | 탈것·병렬 대화 | 보트·배·비행선, 병렬 처리 + 대기(60프레임=1초)로 걸으면서 대화 |
| 5 | 스위치 | 전역 스위치는 맵 공유, 셀프 스위치는 이벤트 전용 |
| 6 | 스위치 응용 | 발판 효과음, 셀프 스위치로 그림 교체, NPC가 다가오는 연출 |
| 7 | 다리 밑 지나가기 | 밟는 순간 스위치를 켜 다리 이벤트를 "캐릭터 위"로 바꾸는 눈속임, 옆으로 새지 않게 보이지 않는 벽, 불투명도로 가려짐 표현 |
| 8 | 추적 이벤트 | 발판을 밟으면 적이 "접근" 자율 이동으로 쫓아옴, 1초 늦게 출발, 닿으면 게임 오버. 사라지게 하려면 더 높은 페이지(스위치 3)로 덮어씀 |
| 9 | 타이머 | 카운트다운 시작·정지. 시간 종료 처리는 별도 병렬 이벤트가 "타이머 ≤ 0초"를 감시해 실행 |
| 10 | 물체 밀기 | 조건 분기 "플레이어가 아래를 보고 있음" → 이벤트를 같은 방향으로 이동. 두 칸짜리 물체를 이벤트 2개로 만들면 어긋나므로 한 장의 그림으로 만든다 |
| 11 | 물체 밀기 응용 | 변수에 물체의 맵 x·y를 넣고, 목표 좌표에 오면 스위치 → 발판으로 변신 |
| 12 | 숫자 암호 | 선택지(누른다/안 누른다) → 숫자 입력(자릿수 지정) → 변수 비교 분기. 틀리면 변수를 0으로 초기화 |
| 13 | 버튼 | 이동 루트의 방향 프레임 바꾸기로 레버 애니메이션, 스위치로 문 열림 페이지 전환 |

## 4. 우리 게임에 가져올 설계 원칙

1. **모든 상호작용은 "조건 → 명령 목록 → 상태 변경"**으로 쓴다. 이 형태는 순수 함수로 옮기기 쉽고 vitest로 검사할 수 있다(`src/sim` 규칙과 맞음).
2. **전역 상태와 객체 상태를 나눈다.** 전역 = 일차·생체지표·퀘스트 진행, 객체 = 상자 열림·NPC 대화 완료.
3. **페이지 우선순위로 상태 변화를 표현**하면 "질환 전단계 → 발병 → 회복"도 같은 틀로 그릴 수 있다(예: 의사 NPC의 대사가 지표 상태에 따라 바뀜).
4. **눈속임을 허용한다.** 다리 밑 통과처럼 실제 구조 대신 표시 순서·불투명도로 해결하는 편이 단순하다.
5. **반복 실행 이벤트는 반드시 끝나는 조건을 둔다.** 병렬 감시자(타이머·추적)는 스위치로 정지한다.
6. **퍼즐 재료는 작게**: 밀기·좌표 확인·암호 입력·버튼. 영양 퀴즈 문(정답 영양소를 입력하면 열림), 음식 상자 밀기 같은 학습 퍼즐로 바꿀 수 있다.
